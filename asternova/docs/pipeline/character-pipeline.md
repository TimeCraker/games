# 角色制作管线

替代旧的 `character-modeling-pipeline.md`、`character-specification-requirements.md`、`character-art-generation-sop.md`（2026-10-23 删除，git 历史可查）。

## 1. 现状

- 游戏里的玩家角色目前是 **CC0 中性人偶**（`client-godot-v2/models/mannequin/`，Quaternius Universal Animation Library），只为让战斗沙盒能跑。
- 白、橙、紫三角色只有**原画和 AI 生成的原始分件模型**，备份在 `art/characters/source/`（说明见该目录 README）。Aster 只有设定图和 Tripo 原始雕刻。没有任何可用的绑定角色。
- 正式角色的"地基"（见第 3 节）**尚未选定，等用户拍板**。

## 2. 旧路线为什么走不通

旧做法是：身体、服装、头发三张设定图分别送 Tripo 生成三个独立模型，再在 Blender 里对齐、用脚本按高度分配权重、手算动画重定向。问题出在地基上，后面怎么修都修不好：

1. **三个部件各自生成，尺度和形状互不对应**。头发模型里带假头，身体模型里带短发，服装与身体之间要靠缩放和变形笼硬套，一动就穿。
2. **AI 生成的脸没有五官几何**，眼睛嘴巴是画在贴图上的，不能眨眼、不能做表情，SDF 面部阴影也无从谈起。
3. **AI 模型没有骨骼和权重**。旧文档写"Tripo 直接生成 Humanoid 骨骼"，实际 9 个 GLB 全部零蒙皮。脚本按 Z 坐标阈值把头、发、领口分给骨骼，头发和衣领因此跟错骨头，攻击时头部后翻、衣服撕裂。

行业里二次元角色的做法是：**先有一个拓扑、五官和骨骼都正确的身体，头发和服装在这个身体上做**。AI 适合出设定图、贴图和道具，不适合直接出要绑定的角色。

## 3. 正确的地基（三选一，待用户决定）

| 方案 | 做法 | 优点 | 代价 |
| :--- | :--- | :--- | :--- |
| **A. VRoid（推荐起步）** | VRoid Studio 按原画捏脸、做发型和服装，导出 VRM | 自带五官几何、表情形态键、Humanoid 骨骼、头发骨骼；Godot 有成熟的 VRM 导入插件 | 默认风格偏"VRoid 脸"，要靠贴图、发型和服装把风格拉开；复杂服装需在 Blender 补 |
| **B. 商用二次元素体** | 购买可商用的 anime base mesh（带面部拓扑与骨骼），头发和服装在 Blender 里在其上制作 | 质量上限高，拓扑和表情是专业做的 | 要花钱、要读许可；服装和头发建模工作量大 |
| **C. AI 一体生成 + 自动绑骨** | 一次生成完整角色（不拆件），AccuRIG 或 Mixamo 自动绑骨 | 最快 | 无表情、头发是硬块、近景不能看；只适合中远景动作镜头 |

无论选哪种，头和脖子、头发和头都来自同一个身体，"头部绑不上"的问题从结构上消失。

## 4. 流程

1. **设定图**：用 `art/characters/source/<角色>/` 里已有的海报和四视图做参考。新角色出图时：纯白背景、正交四视图（正、左、背、右）、微 A-Pose（双臂离体约 40°，双腿分开）、头顶到脚底完整。设定图是给人和工具看的参考，不直接喂给绑定流程。
2. **身体与脸**：按第 3 节选定的地基制作。身体比例按每个角色的海报测量，不套固定头身比。
3. **头发和服装**：在这个身体上做（VRoid 内或 Blender 内），不单独生成后再套。
4. **骨骼与权重**：用地基自带的骨骼（VRM），或 AccuRIG / Mixamo 自动绑骨。服装跟随身体的权重，在 Blender 里用数据传递（Data Transfer）从身体拷贝，并在界面里摆姿势检查。
5. **导入 Godot**：VRM 用 VRM 导入插件，其他用 glTF。在导入设置里配 `BoneMap` + `SkeletonProfileHumanoid`，让项目里的动画能直接重定向到新骨骼。
6. **接入游戏**：新建一个角色场景（参照 `scenes/entities/character_mannequin.tscn`），实例化新模型并挂 `CharacterRig`。按新骨骼改 `hand_bone`、`scabbard_bone` 和握刀/挂鞘的位置朝向，改 `CLIP_ALIASES` 指向新动画。然后在 `player.tscn` 里把 `Character` 换成新场景。
7. **着色**：角色用 `toon_character.gdshader`。面部 SDF 阴影、表情等精修**做出来并实拍验证后**才写进文档的"现状"。
8. **验收**：跑 `tests/test_combat_runner.gd`（插槽、动画、零权重检查），再在 `m1_street` 的四套光照预设下各截一张图，给用户看。

## 5. 规则

- **禁止用脚本按坐标、高度区间分配权重，禁止脚本手算四元数做动画重定向。** 绑定用第 4 节的工具，重定向用 Godot BoneMap。
- **AI 生成（Tripo 等）只用于设定图、贴图、道具和静态物件**，不用于需要绑定的角色本体（方案 C 除外，且接受其局限）。
- **每改一步看图**：几何、权重、材质、光照修改后截图检查，再做下一步。用户看图后的判断是唯一验收，不自报"相似度""分数"。
- **文档只写已经做到的事**。目标和愿景写在 BLUEPRINT，不写成现状。
- 武器与道具按 [weapon-modeling-pipeline.md](weapon-modeling-pipeline.md)。
