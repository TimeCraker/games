# AsterNova 3D 武器与道具工业化制作管线指南（Weapon Modeling Pipeline SOP）

> **文档定位**：本项目所有 3D 武器（刀剑、长枪、法器、弓弩等）与可穿戴道具的**唯一技术实践与标准化复刻指南**。
> **基准参考案例**：Aster 专属佩刀「**星霜月华**」（Seisou Gekka · 899 三角面 · 双分件可拔刀结构）。
> **生效时间**：2026-09-04 起生效，后续所有武器资产制作必须按本 SOP 进行拓扑、拆件、贴图绘制与双引擎验收。

---

## 1. 核心设计与工程哲学

商业级二次元高刷动作游戏（对标《鸣潮》《绝区零》《崩坏：星穹铁道》）中，武器不仅是视觉焦点，更是高频战斗动画与复杂粒子特效的核心承载物。制作必须贯彻三大原则：

1. **「简约好看、轻量高性能」原则（Budget-First）**：
   - 原画设计往往极致华丽，但 3D 资产**绝对严禁雕刻微观繁复雕花或堆叠细碎倒角面**；
   - 抓准**修长微弧的剪影、核心大块面特征（如星芒护手、系绪蝴蝶结）与色彩通透度**即可；
   - 几何细节不足处，全部依托高质量 2D NPR 贴图刻线与材质反光体现，为 120 FPS 高刷留足开销。
2. **零偏置可拔刀装配架构（Zero-Offset Dual-Mesh Architecture）**：
   - 武器与刀鞘在建模阶段彻底拆分为两套独立的 Mesh；
   - **原点必须严格统一锁定在【刀鞘口（Koiguchi）正中心】`(0, 0, 0)`**；
   - 入鞘状态下两分件坐标均为 `(0,0,0)`；拔刀时仅需沿局部特定单轴（如 `+Z` 轴）线性位移即可出鞘，彻底消除战斗动画师与程序的手动对齐和穿模噩梦。
3. **闭环双模验证交付（Double-Loop Inspection）**：
   - 资产必须同时通过 **Godot 4.7 引擎实时检视** 与 **自包含 3D Web 检视器** 双重验证；
   - 交付物必须包含：多视角高精对比看板（PNG）、Blender 源工程（.blend）、游戏标准资产（.glb）、贴图图集（.png）、以及可交互 360° 检视场景。

## 2. 性能预算与拓扑规范

| 资产类型 | 三角面预算 (Tris) | 顶点预算 (Verts) | 材质槽数量 | 贴图规格 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **单手轻兵装（太刀/单手剑/匕首）** | **800 ~ 1,500** | **500 ~ 900** | 1 (Draw Call 严控) | 2048x2048 Atlas | 角色随身佩带、极速拔刀斩击 |
| ├─ 刀身分件 `Blade_Mesh` | 500 ~ 900 | 300 ~ 550 | 共用图集 | 刀刃、刀镡护手、刀柄、吊坠 | 战斗握持于右手骨骼插槽 |
| └─ 刀鞘分件 `Scabbard_Mesh` | 300 ~ 600 | 200 ~ 350 | 共用图集 | 刀鞘、鞘口包金、系绪缎带、鞘尾 | 常态悬挂于左腰封插槽 |
| **双手重兵装（大剑/长枪/战镰）** | 1,500 ~ 2,500 | 900 ~ 1,500 | 1 | 2048x2048 Atlas | 双手大开大合挥砍 |
| **射击与法器类（悬浮浮游刃/法杖）** | 600 ~ 1,200 | 400 ~ 800 | 1 | 1024x1024 或 2048 | 环绕角色自转悬浮 |

### 拓扑红线：
- **严禁使用布尔运算（Boolean）残留杂面**：必须手工整理为干净的四边面（Quad）再三角化，严禁出现 N-gons（五边及以上多边形）或孤立飞点；
- **刀刃切先（Kissaki）拓扑**：刃脊线（Shinogi line）必须清晰延伸至刀尖，刀背、刃面与反向斜切面在刀尖交汇于单一锋锐顶点；
- **圆柱形截面段数控制**：刀柄与刀鞘截面采用 **8 边形或 10 边形**，配以平滑着色（Smooth Shading），视觉圆润度足够，杜绝 16/32 边形导致的冗余面数。

## 3. 零偏置可拔刀分件架构（Dual-Mesh System）

```
                     [ Koiguchi 原点 (0,0,0) ]
                               │
       ┌───────────────────────┴───────────────────────┐
       ▼                                               ▼
[ Blade_Mesh (刀身组) ]                     [ Scabbard_Mesh (刀鞘组) ]
- 局部坐标: (0, 0, 0)                       - 局部坐标: (0, 0, 0)
- 轴向伸展:                                 - 轴向伸展:
  · 刀刃: Z 从 0.0m 延伸至 -0.70m             · 鞘身: Z 从 0.0m 延伸至 -0.72m
  · 护手: Z 位于 0.0m ~ +0.008m               · 缎带蝴蝶结: Z 位于 -0.05m
  · 刀柄: Z 从 +0.008m 延伸至 +0.25m          · 鞘尾包角: Z 位于 -0.72m
  · 吊坠: Z 位于 +0.25m ~ +0.33m
- 挂载骨骼: Hand_R_Weapon_Socket             - 挂载骨骼: Pelvis_L_Scabbard_Socket
```

### 3.1 拔刀动画数学逻辑
1. **入鞘待机态（Sheathed State）**：
   ```gdscript
   blade_mesh.position = Vector3.ZERO
   blade_mesh.rotation = Vector3.ZERO
   ```
   刀身完全藏于刀鞘内部，刀鎺（Habaki）严丝合缝卡于鞘口，外表呈现一把完整的佩刀。
2. **居合出鞘态（Unsheathed State）**：
   ```gdscript
   # 沿刃身局部 +Z 轴抽出 0.74m（刃长 0.70m + 余量 0.04m）
   var draw_offset = Vector3(0.06, 0.02, 0.74) # 微小 X/Y 偏移用于展陈并列
   blade_tween.tween_property(blade_mesh, "position", draw_offset, 0.25)
   ```
3. **战斗挂载切换（Socket Re-parenting）**：
   - 战斗拔刀时：`Blade_Mesh` 的父节点动态挂载至角色的右手机械骨骼插槽 `Hand_R_Weapon_Socket`；
   - `Scabbard_Mesh` 始终保留在角色腰部插槽 `Pelvis_L_Scabbard_Socket`，或在左手持鞘格挡时挂载至左手。

## 4. 曲率与几何造型技术（以日本太刀为例）

### 4.1 反曲线数学方程（Sori Curve）
真实刀剑具有优雅的微反弧度（Sori）。在程序化或网格构建中，建议采用分段平滑抛物线控制：
```python
def sori(z):
    # z > 0 为刀柄部分，采用反向微倾保证握持人体工学
    if z > 0:
        return -0.002 * (z / 0.25)
    # z < 0 为刀刃与刀鞘部分，向背部产生 18mm 的优雅微弧
    t = abs(z) / 0.70
    return 0.018 * (t ** 1.35)
```

### 4.2 鎬造截面（Shinogi-zukuri）
刀身截面为五边形：
- 刀背（Mune）：扁平微倒角，宽度约 4.5mm；
- 刃脊（Shinogi）：刀身最厚处，宽度约 5.5mm；
- 刃面（Ha）：向前方收窄至 0.4mm 刀刃线（低模无需做出纳米级刃口，0.4mm 结合法线着色既锐利又杜绝烘焙走样）。

### 4.3 四芒星立体镂空护手（Tsuba）
- 四方向放射花瓣（长轴 6.8cm，短轴 4.2cm，厚度 3.6mm）；
- 表面带有象牙白内衬与中央金色镶钻，低模使用 24~36 个三角面即可表现出极为立体的几何光影。

### 4.4 系绪蝴蝶结（Sageo Ribbon）
- 位于鞘口下方 5cm 处；
- 构造包括：中心束结核（Box/Knot） + 两个上扬环形回折（Loops） + 两根自然下垂并随风微摆的飘带（Draping Tails） + 金色金属收尾封头（Aglet）。

## 5. 贴图图集（Texture Atlas）与 NPR 材质工艺

### 5.1 UV 象限与布局规范
整套佩刀共用一张 `2048x2048` BaseColor 图集（`tex_katana_basecolor.png`），象限分配如下：

```
(0, 1) ┌───────────────────────────┬───────────────────────────┐ (1, 1)
       │                           │                           │
       │     A. 刀鞘主体 (Saya)     │     B. 刀身钢材与刃纹     │
       │     象牙白微珠光基底      │        (Blade Steel)      │
       │     金色四芒星阵列纹样     │    冷天蓝渐变 + 烧刃纹波浪 │
       │                           │                           │
(0, 0.5)├───────────────────────────┼───────────────────────────┤ (1, 0.5)
       │                           │  E. 宝石与辅色 (Gems)     │
       │     C. 刀柄柄卷 (Tsuka)    ├───────────────────────────┤
       │     深蓝菱形目贯编织纹    │  D. 缎带蝴蝶结 (Ribbon)   │
       │     金色小金具与目贯      │  浅蓝缎带渐变 + 纯白镶边  │
(0, 0) └───────────────────────────┴───────────────────────────┘ (1, 0)
```

### 5.2 材质配色规范（Hex 标定）
必须严格继承 `docs/STYLE.md` 的色彩规范：
- **象牙白微珠光（刀鞘主体 / 护手嵌件）**：`#E0E0E8`（杜绝纯白 `#FFFFFF` 防止爆光）；
- **香槟微金（护手 / 鞘尾 / 柄尾 / 铭牌）**：`#EBC57A`（金属感 0.85，粗糙度 0.28）；
- **深邃冷蓝（刀柄柄卷）**：`#18243B` 至 `#223E75`；
- **通透浅蓝（系绪缎带 / 吊坠丝带）**：`#8AC2EB`（明媚柔和，与 Aster 发饰互应）；
- **水蓝星钻宝石（中心镶嵌）**：`#5FD2EE`（微发光，高光通透）；
- **刀刃特级钢材**：刃脊 `#DCE8F5`，刃口向刀背过渡为冷青白，带有细腻的波浪形烧刃纹（Hamon）。

### 5.3 描边规范（Inverted Hull Setup）
- **修改器配置（Blender）**：
  - 类型：`SOLIDIFY`（实体化）
  - 厚度：`0.0009m`（0.9毫米，武器尺度小，严禁过粗）
  - 偏移：`1.0`
  - 法线：开启 `Flip Normals`（翻转法线）
  - 边缘：关闭 `Rim`
  - 材质偏移：指向描边专用材质槽（深灰青蓝 `#3D435C`，纯 Unshaded 无光照受光）。

## 6. 双引擎资产导出与工程接入规范

### 6.1 Blender 5.2 GLTF/GLB 导出标准
使用 Python 脚本或导出面板执行时必须设置：
```python
bpy.ops.export_scene.gltf(
    filepath="aster_katana.glb",
    export_format='GLB',
    use_selection=True,           # 仅导出 Blade_Mesh 与 Scabbard_Mesh
    export_apply=True,             # 应用修改器（应用 Inverted Hull）
    export_yup=True,               # 转换为 Y 轴朝上（游戏引擎标准）
    export_tangents=True,          # 导出切线数据供各向异性使用
    export_materials='EXPORT',     # 导出材质
    export_image_format='AUTO',    # 保持贴图品质
)
```

### 6.2 Godot 4.7 引擎高效加载准则
- **避免臃肿场景**：严禁把包含 Base64 嵌入贴图的整个 GLB 打包成数十兆的 `.tscn`；
- **标准动态接入**：在游戏或检视场景中使用 `GLTFDocument` 毫秒级原生解析：
  ```gdscript
  var gltf = GLTFDocument.new()
  var state = GLTFState.new()
  var err = gltf.append_from_file("res://models/weapons/aster_katana/aster_katana.glb", state)
  if err == OK:
      var katana_node = gltf.generate_scene(state)
      add_child(katana_node)
  ```

## 7. 全维度 360° 交互检视与验收工具链

为避免模型在静态角度看似合格、而在 360° 动态转动或实机中穿帮，必须标配三套检视手段：

1. **自包含 3D Web 检视器（`aster_katana_3d_viewer.html`）**：
   - 特点：单文件内嵌 Base64 GLB 模型与 Three.js 引擎，文件仅 160KB，**双击即可在任何浏览器（Chrome/Edge/Safari）秒开**，零跨域、零后端依赖；
   - 交互能力：鼠标左键 360° 自由环绕旋转、滚轮无级缩放、空格键拔刀/收刀动画、`W` 键一键切换**线框拓扑模式（Wireframe）**审查面数分布、`1~5` 快捷键特写对焦；
   - 价值：任何人无需安装 Godot 或 Blender 即可立刻评审。
2. **Godot 4.7 引擎实时交互场景（`render-lab/scenes/weapon_viewer.tscn`）**：
   - 在游戏原生渲染管线（Toon Shader、MSAA 3D、Glow 泛光、日落环境）下审查武器的受光折射。
3. **自动化超高分辨率合成看板（`katana_preview.png`）**：
   - 包含：① 入鞘全身透视、② 拔刀并列展陈、③ 四芒星护手特写、④ 刀尖切先与刃纹特写、⑤ 刀柄与星芒吊坠特写。附带模型技术参数标牌（面数、材质、骨骼挂点）。

## 8. 新武器快速复刻执行清单（SOP 8 步法）

当制作下一把新武器时，严格按以下 8 步执行：

- [ ] **Step 1: 视觉基准锁定**：获取并审查 2D 正交全分件设定图（全长、刃长、柄长、截面、正交顶/侧视图）。
- [ ] **Step 2: 拆件与原点标定**：确定武器分件（如刀刃 + 刀鞘，或弓身 + 箭矢），**统一将分件的局部原点对齐在插槽锁扣中心 `(0,0,0)`**。
- [ ] **Step 3: 几何低模雕刻**：用最简块面搭建形体，主手武器严控在 800~1,500 三角面。
- [ ] **Step 4: 贴图图集绘制与 UV 展开**：在单张 2048x2048 图集中完成色彩、暗部色偏与金属质感绘制，遵守 `docs/STYLE.md` 配色。
- [ ] **Step 5: 描边装配**：挂载 Inverted Hull（Solidify 翻转法线，厚度 0.9mm，深青灰描边）。
- [ ] **Step 6: 双引擎无头导出与验证**：导出为标准 `.glb`，并在 Godot 4.7 与 Blender 5.2 中无头加载，确保 0 报错、0 孤立点。
- [ ] **Step 7: 生成 360° 交互检视器**：
  - 更新/生成 Web 单文件 3D 检视器（支持 360° 环绕、拔刀补间与线框检查）；
  - 更新/运行 Godot 检视场景。
- [ ] **Step 8: 产出多视角验收看板与 Git 提交**：生成高分辨率组合看板，以 `feat(art): 完成 [武器名称] 3D 建模与可拔刀分件装配` 规范提交。
