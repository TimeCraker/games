# 星域突围 · UI / 美术前端设计规格

> 配套文档：玩法锚点 `docs/nebula-survivor-whitepaper.md` · 品牌约束 `docs/STYLE.md §5` · 网站工艺规则 `docs/ui-polish/rules.md`
> 状态：M0 定稿。任何 UI 改动必须引用本文条目；本文没写的，先补录再实现。
> 核心前提：**主站已经是「遥测台语言」**（大厅的琥珀网格、四角括号、序号、等宽读数、薄玻璃面板）。游戏内继承同一套组件语法 —— 玩家从大厅点进来，视觉应像「同一台仪器的下一个界面」，而不是另一款游戏的皮。

---

## 1. 三层设计语言

所有游戏内视觉都由这三层拼出，不得引入第四种语言。

| 层 | 作用 | 配方（单一真源） |
|---|---|---|
| **底板层** | 铺满视口的空间底 | 冷中性黑三段渐变 `#0b0d12 → #08090d → #050608`（`NB_BG`）；琥珀星图网格（复用 `.arcade-letterbox` / `.star-chart-grid` 的网格母题）；大半径暗角 |
| **面板层** | 承载信息的玻璃盒 | `PanelCorners` 四角括号 + 1px `white/10` 边 + `bg-surface-2/80` + `backdrop-blur-glass-md` + 内高光 `inset 0 1px 0 rgba(255,255,255,.06)` |
| **数据层** | 读数与标签 | 数值 `font-mono-data` + `tabular-nums`；小标 `tracking-[0.14em]` 大写；强调色**只允许单一琥珀**（`text-hud-accent` / `text-hud-accent-bright`） |

**禁止**：紫/品红/高饱和青蓝；霓虹外发光；蓝紫渐变；纯 `#000` 大面积平铺（用 `--ink-1000`）；超过一种强调色混排正文。

## 2. 色彩系统

### 2.1 角色分工

| 语义 | token | 值 | 用在哪 |
|---|---|---|---|
| 空间底 | `--ink-1000` … `--ink-600` | `#050607` … `#22262B` | 底板、面板、分隔线 |
| 文本 | `--fog-100` … `--fog-400` | `#E2E5E8` … `#6B7480` | 正文 / 次级 / 弱 |
| **UI 强调** | `--amber-500` / `--amber-400` | `#D8A33C` / `#E9BE69` | 数值、CTA、我方、雷达扫描线 |
| 我方/玩家 | `#D8A33C`（琥珀） | — | 舰体、弹幕、XP 结晶 |
| 危险 | `--signal-red` | `#C0503A` | 敌方三档、受击、结算失败 |
| 副色（本作） | `--arcade-nebula` | `oklch(0.74 0.1 132)` 青柠苔绿 | **只作 2★ 品级色与雷达网格刻度**，不进正文 |

### 2.2 品级色板（见白皮书 §5.2）

`1★ --paper` / `2★ --arcade-nebula` / `3★ --arcade-shoot` / `4★ --amber-500` / `5★ --signal-red`

**档次靠工艺单调编码，不靠色相**：

| 档 | 边框 | 底 | 附加 |
|---|---|---|---|
| 1★ | 1px `white/12` | — | — |
| 2★ | 1px 品级色 `/35` | 品级色 `/10` | — |
| 3★ | 1.5px 品级色 `/55` | 品级色 `/12` | 内发光 `inset 0 0 12px 品级色/18` |
| 4★ | 2px 品级色 `/70` | 品级色 `/14` | 外辉光 `0 0 18px 品级色/25` |
| 5★ | 2px 品级色 `/85` | 品级色 `/16` | 外辉光 + **流光扫过动画**（`--duration-ambient` 循环） |

**红线**：品级色**只允许**出现在武器槽 / 武器卡边框与徽记上；UI 强调色（琥珀）不得进入该区域，避免「传说武器和血条同色」。

### 2.3 对比度
正文 ≥4.5:1；≥24px 或 ≥18.66px 粗体大字 ≥3:1；文字透明度地板 `text-white/50`。

## 3. 字体与排版

| 用途 | 字体 | 配方 |
|---|---|---|
| 品牌大字（开场/结算） | Orbitron | `.aster-title`，色 `var(--paper)` |
| 正文 / 按钮 | Geist Sans | `text-[13px] sm:text-sm` |
| 数据 / 坐标 / 读数 | JetBrains Mono | `font-mono-data` + `tabular-nums` |
| 小标（eyebrow） | Geist | `uppercase tracking-[0.14em] text-[10px] text-white/50` |

**局内字号阶梯（真实 CSS px，因为 HUD 已在缩放容器外）**：`10 / 11 / 12 / 14 / 18 / 24 / 34`。
下限：**局内 HUD 任何可见文字 ≥12px**（白皮书 §11.7 验收）。

## 4. 局内 HUD

### 4.1 分区

```
┌───────────────────────────────────────────────────────────┐
│ ① 左上 生存数据        ② 中上 品牌      ③ 右上 系统键      │
│  WAVE / LV / HP / XP              音效 · 暂停 · 规则       │
│                                                           │
│  ④ 游玩区（Pixi 画布）        ⑤ 游玩区右侧 环形雷达        │
│                                                           │
│ ⑥ 左下 摇杆      ⑦ 底部中央 武器槽 ×3      ⑧ 右下 E 技环   │
└───────────────────────────────────────────────────────────┘
```

### 4.2 各区块规格

- **① 生存数据**（`ui/Hud.tsx`，`PanelCorners` 玻璃盒）
  `WAVE nn` + `LV n` 一行 → `HudMeter` HP（`variant="hp"`）→ `HudMeter` XP（`variant="xp"`）→ 分隔线 → `击杀 / 得分 / 威胁` 三个 `HudStat`。
  **宽度响应式**：`w-[13.5rem] sm:w-64`，**不再是固定 `15rem`**。
- **② 品牌**：`BrandMark slug="nebula-survivor"`，小屏仅留图标 + `text-[9px]` 中文，**禁止换行错位**（旧版真机两行竖排是 bug）。
- **③ 系统键**：图标按钮（音效）+ 文字按钮（暂停/规则）。**必须 `whitespace-nowrap` + `shrink-0`**，防止 1440px 下文字竖排换行。视觉盒 ≥32px，命中盒 ≥44px（伪元素法）。
- **⑤ 环形雷达**（`ui/Radar.tsx`，复用 `HudRadar` 图标 + `.reticle-ring`）
  半径 56px（小屏 44px）；中心 = 玩家；**敌方光点按方位角分布**；扫描线 2.6s 一圈（`--duration-ambient`）；青色只用 `--arcade-nebula` 刻度，不用高饱和青蓝。
  雷达同时承担「威胁」语义 —— ③ 区的「威胁」文字读数可保留但不再是唯一威胁信息。
- **⑦ 武器槽**（`ui/LoadoutBar.tsx`）—— 本作最核心的新系统
  3 个槽位，每槽显示：武器图标（`HudSwords` / `HudTarget` / `HudHexGem` 等）+ 星数（`★n`）+ **合成刻痕 `n/3`**（同星同名计数，差 1 个时高亮脉冲）。
  边框走 §2.2 品级工艺。空槽为虚线 `white/10`。
- **⑧ E 技环**（`ui/SkillRing.tsx`）
  圆形冷却环（conic-gradient）+ 技能图标 + 剩余冷却秒数（`font-mono-data`）。就绪时琥珀描边脉冲，冷却中降透明度至 `/45`。
- **⑥ 摇杆**：**仅在 `(pointer: coarse)` 时渲染**（旧版桌面也画摇杆是浪费屏幕）。

### 4.3 响应式规则

| 断点 | 变化 |
|---|---|
| 桌面 ≥1024px | 全展开；摇杆隐藏；系统键显示文字 |
| 平板 640–1023px | 品牌行压缩；系统键保留文字 |
| 手机 <640px | 系统键只留图标（aria-label 保留）；生存数据缩为 `w-[13.5rem]`；雷达缩到 44px；武器槽改底部横排、槽位 56px |

**竖屏手机**：HUD 分区不变，游玩区自然变窄变高；相机按纵横比自适应（§6.2）。**不做旋转提示、不做 letterbox**。

## 5. 局外与弹层

- **简报 / 暂停**：`ArcadeEntry`（`variant="drawer"`，420px，玻璃，底部抽屉）。briefing **不传 `onRequestClose`**。
- **船坞 Hangar**：同一套玻璃面板语言，三块 —— 职业选择（5 张舰船卡，选中态琥珀描边）/ 武器库（10 把，品级工艺）/ E 技升级（5 条，等级刻度）。
- **商店**：网格卡片 + 品级工艺 + 价格读数；「刷新」按钮显示剩余免费次数。
- **合成 / 背包**：3 槽 + 「合成」按钮；可合成时按钮琥珀高亮 + 刻痕脉冲。
- **结算**：`ArcadeResult`，标题按最长单词反推字号；失败态用 `--signal-red`。

## 6. 游戏内美术

### 6.1 技术路线（M0 定稿）
**程序化矢量为主**：Pixi `Graphics` 绘制，赛璐璐三色调（`TONES`：base / shadow / hi / outline）。零位图依赖 → 数据驱动、零美术等待、天然满足白皮书 §11.2。
位图只用于：大厅 key art、Boss 立绘（如需）。

### 6.2 相机与可见范围
- 玩家居中（沿用 `camera.position.set(viewW/2 - player.x + shake)`）。
- **可见范围基准**：以「短边 ≥900 世界单位」计算缩放，保证任何纵横比下都能看到足够的战斗信息。
- 有地形后，相机不穿墙（可选 M4 优化）。

### 6.3 实体可读性（白皮书 §11.8）
| 实体 | 世界半径 | 说明 |
|---|---|---|
| 玩家舰体 | 14 | 实测 1440×900 下过小，M3 提升到视觉直径 ≥28 真实 px |
| 小怪 | 10–18 | 按三档递增 |
| 子弹 | 3–5 | 琥珀弹幕，配 outline 保证暗底可辨 |
| 掉落 | 5 | 琥珀结晶 + 呼吸发光 |

**敌方三档配色**（沿用，低饱和）：珊瑚 `0xc08069` / 翠玉 `0x7fb39e` / 信号红 `0xc0503a`，各配 rim 高光与深描边。

### 6.4 地图语言
废弃矿星 / 轨道站残骸：冷灰金属硬表面 + 琥珀信号灯。墙/掩体/通道用**明度差**区分（可通行区偏亮、掩体偏暗 + 描边），不用高饱和色块。

## 7. 动效清单

| 时机 | 动效 | 时长/token |
|---|---|---|
| 悬停 / 微交互 | 亮度 + 边框 | `--duration-fast` 200ms，`--ease-instrument` |
| 面板进场 | 位移 + 淡入 | `--duration-base` 500ms，`--ease-cinematic` |
| **三合一升星** | 镜头微推 + 品级色冲击环 + 音效 | 900ms，唯一「仪式感」高光时刻 |
| 拾取武器 | 槽位弹跳 + 品级色描边闪 | 300ms |
| E 技就绪 | 描边脉冲 | 循环 2.6s |
| 受击 | 屏幕红闪 + hit-stop | 现有 `scene.hitStop` |
| 5★ 武器卡 | 流光扫过 | 循环 `--duration-ambient` |

**禁止**：线性/ease-in-out 过渡；动画 `top/left/width/height`（只用 `transform`/`opacity`）；霓虹外发光。

## 8. 图标

复用 `src/components/icons/arcade-icons.tsx` 既有集（`HudRadar` / `HudShield` / `HudBolt` / `HudTicks` / `HudHexGem` / `HudSpark` / `HudTarget` / `HudSwords` / `HudSignal`…）。
**不引入 Lucide 作默认图标**（`lucide-react` 已在依赖中，仅允许系统类图标如音量/暂停继续使用）。

## 9. 验收清单（M3 过目门）

1. 桌面 1440×900 + 真机移动 UA（390×844）双端截图。
2. DOM 探针数据：HUD 实测像素尺寸、最小文字实际字号 **≥12px**、关键路径命中盒 **≥44px**、无横向溢出。
3. 无 letterbox 条带（画布填满视口）。
4. 品级 5 档工艺可辨（截图逐档）。
5. 禁色 grep 命中 0。
6. 画面**持续演进**取证（连拍两帧比对，不能只看静态首屏）。
7. 制作人肉眼过目「好看且可读」后才进 M4 批量。
