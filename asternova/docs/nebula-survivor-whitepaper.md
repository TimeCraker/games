## 1. 定位与核心体验

- **品类**：俯视角存活类肉鸽（Survivors-like）。**自动索敌、玩家只负责走位 + 放 E 技 + 合成构筑**。
- **核心幻想**：驾驶一艘船，在星域里刷怪、捡/买武器、**三合一合成升星**，一局 4~8 分钟越打越强。
- **去传统化的关键（相对旧版与市面同类）**：
  1. **砍掉「升级三选一」**，主轴换成「捡/买武器 + 三合一升星」的构筑。
  2. **法术 = 引力/空间场**（不是火球法师），与近战/远程天然区分。
  3. **有地形的地图**（墙/掩体/通道），走位更有讲究。
  4. **职业 = 船 = 数值倾向 + 专属武器 + 专属 E 技**的组合，而非硬造虚假武器属性。

---

## 2. 核心循环

**局内（一局 4~8 分钟）**

进入有地形的图 → 打怪掉(金币/经验) → 捡/买武器 → 三合一升星(或直接花钱升) → 商店买武器/升 E 技 → 遭遇小怪潮 → 挑战 Boss → 随时可撤（无惩罚、不强制击杀 Boss）

**局外（出去后）**

金币 → 买各职业武器 + 升级 E 技能 ；经验 → 升角色基础数值（攻击 / 防御 / 法术值）；职业全解锁。

---

## 3. 操作与输入

- **移动**：摇杆（手机）/ WASD·方向键（PC），沿用现有左下虚拟摇杆思路。
- **攻击**：自动索敌、自动开火，无需手动瞄准。
- **E 主动技**：一个 E 键/按钮 + 冷却（纯「走位/生存」向，无输出型）。

---

## 4. 职业系统（首发 5 个，均已定稿）

职业 = ① 基础数值倾向 + ② 专属武器（3 把，取自 §5 武器池） + ③ 专属 E 技。**不再新增武器属性维度。**

| 职业 | 数值倾向 | 专属武器（3 把） | 专属 E 技 |
|---|---|---|---|
| **格斗舰**（近战） | 高攻·高防 | 撞角 / 回旋刃 / 牵引钩 | 闪现 |
| **炮舰**（远程） | 高攻·低防 | 散射炮 / 追踪导弹 / 穿透狙击 | 尾焰疾驰 |
| **引力舰**（法术） | 高法·低物防 | 引力井 / 斥力波 / 空间裂缝 | 护盾 |
| **重装舰**（坦克） | 超高防+盾·攻低 | 撞角 / 牵引钩 / 回旋刃 | 装甲充能 |
| **机动舰**（刺客） | 高移速高爆·脆 | 快刀 / 回旋刃 / 牵引钩 | 量子回跳 |

> 重装/机动是「数值倾向 + E 技」换调性的组合（肉盾 / hit-and-run），不是新武器属性，故不与近战/远程/法术撞车。首发即上这 5 个。

## 5. 武器系统

### 5.1 三系（已去重，砍掉召唤/弹射/资源爆发）

**武器池共 10 把**，每职业从池中取 3 把（见 §4）：

- **近战（4）**：撞角 / 回旋刃 / 牵引钩 / 快刀
- **远程（3）**：散射炮 / 追踪导弹 / 穿透狙击
- **法术（3）**：引力井（聚怪+持续伤）/ 斥力波（推开+伤）/ 空间裂缝（定点持续伤）

一句话区分：**远程是「子弹飞过去」，法术是「在地上/空间放一个场」。**

**武器槽**：单局最多同时持有 **3 把**武器（槽位 UI 见 §14.4）。

### 5.2 品级（5 档 · 直接映射品牌已验证 token）

`1★ 普通 → 2★ 优秀 → 3★ 稀有 → 4★ 传说 → 5★ 神话`

| 档 | 语义 | token（单一真源） | 工艺编码 |
|---|---|---|---|
| 1★ | 普通 | `--tier-1` = `var(--paper)` `#F2F4F5` | 1px `white/12` 边，无光 |
| 2★ | 优秀 | `--tier-2` = `var(--arcade-nebula)` `oklch(0.74 0.1 132)` 青柠苔绿 | 1px 边 + 12% 底色 |
| 3★ | 稀有 | `--tier-3` = `var(--arcade-shoot)` `oklch(0.75 0.08 205)` 钢青 | 1.5px 边 + 内发光 |
| 4★ | 传说 | `--tier-4` = `var(--amber-500)` `#D8A33C` 琥珀金 | 2px 边 + 琥珀辉光 |
| 5★ | 神话 | `--tier-5` = `var(--signal-red)` `#C0503A` 信号红 | 2px 边 + 红辉光 + 流光动画 |

**这段色板的依据（v1 在此处与品牌红线冲突，v2 修正）**：

- 品牌副色在 `globals.css` 中已被硬约束在**同一亮度带**（`L 0.74–0.78`、`C 0.08–0.11`、低饱和）。直接复用它们，品级色自动满足品牌约束，且天然避开高饱和霓虹。
- `ui-polish/rules.md §12` 警告「生成坡道必须避开绿（90–160°）」——那是指**线性插值生成的绿**。2★ 直接锚定官方定义好的 132° 青柠苔绿 token，不是自己调一个绿。
- **4★（琥珀）与 5★（红）的语义撞车靠工艺解决**：琥珀同时是 UI 强调色、5★红同时是危险/失败信号色，因此：
  - 档次靠**工艺单调**编码（细边无光 → 细边+底 → 中边+内发光 → 粗边+辉光 → 粗边+红光+流光），玩家靠工艺就能读档，不依赖色相；
  - **红线：品级色只允许出现在武器槽 / 武器卡边框与徽记上，UI 强调色不得进入该区域。**

**品牌红线（不变）**：冷中性黑底 + 单一琥珀金主色 + 青柠苔绿副色；**禁紫 / 品红 / 高饱和青蓝**。

### 5.3 升星规则（两条路径并存，简单不加花）

- **三合一**：3 个同名同星 → 合成升 1 星。
- **直接花钱**：花金币给某把武器直升 1 星（不必凑三个）。
- **商店购买**：图内商店直接出售武器（含高星）。
- 升星**只加伤害、可加射程/范围**，不引入随机词条（此前「词条随机」已被否决为偏复杂）。
- **星级上限**：局内即可达到 5★。前期靠三合一，后期靠金币；金币是主要瓶颈（曲线 M4 定）。

## 6. E 主动技（首发 5 个，均已定稿；纯走位/生存向）

1. **闪现**：短距离位移（是否穿墙/距离/无敌帧用参数调，不另做「冲刺」）
2. **护盾**：短时吸收/无敌
3. **尾焰疾驰**：短时大幅提速 + 尾迹
4. **装甲充能**：回血 / 回盾
5. **量子回跳**：按一下记录位置，再按一下瞬移回该位置

> 备用池（后续解锁，暂不做）：相位穿越（穿墙/穿怪）、净化脉冲（解控，待 Boss/小怪定后再决定）。

- 由旧版「无限平地 + 网格」改为**有限竞技场 + 墙 / 掩体 / 通道**。

- **主题**：废弃矿星 / 轨道站残骸（与主站的星图·遥测母题同源，且天然提供矿道=通道、舱段=掩体、岩壁=墙）。

## 9. 经济与局外养成

- **局内经济**：打怪掉金币与经验；图内商店花金币**买武器 / 升 E 技 / 直升星级**。
- **局外养成**：金币 → 永久买各职业对应武器 + 升级 E 技能；经验 → 升角色基础数值（攻击 / 防御 / 法术值）；职业全解锁，无解锁线。
- **重玩动机（v2 补充，v1 缺失）**：全解锁 + 局外成长会消解进度压力，故重玩驱动明确落在 **① 冲击更高波次/分数（大厅 best 记录）② 收集 10 把武器与 5 职业的满级形态 ③ 难度层级**上。难度层级是否首发上线在 M4 定。
- 具体数值/定价**M4 单独设计**，本条锁定结构。

## 10. 美术 / UI 方向

### 10.1 主题
宇宙星球风（沿用 AsterNova 主风格）。主站已是「遥测台语言」，游戏内**继承同一套组件语法**，不另起一套：玩家从大厅点进来，视觉应像「同一台仪器的下一个界面」。

### 10.2 品牌红线
冷中性黑底 + 单一琥珀金主色 + 青柠苔绿副色；**禁紫 / 品红 / 高饱和青蓝**。验收口径：`grep -E 'violet|fuchsia|purple|indigo|pink-[0-9]|cyan-[0-9]'` 在 `src/components` 命中为 0。

### 10.3 大厅 key art
现精选卡用的是 NASA 猎户座星云原色，呈紫/品红，**违反 10.2 红线**（代码 grep 抓不到图片层）。修法：把 `fetch-arcade-art.mjs` 中 `nebula-survivor` 的 `grade` 改走脚本已有的 `duotone` 通道（复用 `xiaoxiaole` 的现成写法），并重跑脚本 + `keyArt.ts`。

### 10.4 详细规格
三层设计语言、HUD 分区、雷达、武器槽、动效清单 → 见 `docs/nebula-survivor-ui-spec.md`；共享视觉变量 → 见 `STYLE.md §5`。

## 11. 成功标准（验收口径 · v2 扩为 9 条）

1. 逻辑层与渲染/UI 解耦，模拟核心为纯 TS、可确定性测试、无 DOM 依赖。
2. 新增武器/职业/敌人只改数据，不改引擎代码。
3. 内容峰值（3000 敌 + 400 子弹）下移动端稳定 60fps（实测帧时间 P95）。
4. 一局能形成 ≥3 种明显不同流派（三条职业线 + 合成差异）。
5. UI 组件化 + 游戏专属设计 token，无单文件 >500 行的 God Component。
6. 有确定性单测 + 性能基准，验证不靠「模型自称 PASS」。
7. **双端 HUD 实测**：桌面 1440×900 与**真机移动 UA** 下，局内 HUD 实际渲染字号 **≥12px**、无 letterbox 条带、关键路径命中盒 **≥44px**。
8. **战斗可读性**：玩家舰体与敌人在实际分辨率下的最小可辨尺寸达标；威胁有**方位**提示（雷达），不是只有一个抽象等级。
9. 确定性：同种子 + 同输入流回放 → 快照 hash 一致。

> 第 7 条是 v1 最大的漏洞：v1 只写了 60fps 性能口径，没写「一屏内玩家能读到什么」，导致旧实现真机下 HUD 折合 4.6px 仍「符合白皮书」。

## 12. 补充决议（v1 列为「待定」的三项，v2 定稿）

1. **武器池容量与三合一可达成性**：池 = 每职业固定 3 把（全局 10 把定义，见 §5.1）；三合一 3 个同名同星 → +1 星；单局可到 5★，前期靠三合一、后期靠金币直升，**金币是主要瓶颈**。
2. **局内商店刷新机制**：商店在固定波次节点开启；**每次进店免费刷新 1 次**，其后每次刷新消耗递增金币（数值 M4 定）。
3. **手机屏向策略**：**不锁横屏、不做旋转壳、不做 letterbox**。游戏画布填满视口，相机按任意纵横比自适应；HUD 用真实 CSS px 的响应式布局，且**绝不放进任何 `transform: scale()` 容器**（详见 §16.4 与 `ui-polish/rules.md` 新增一节）。

### 仍未定（M4 处理）
Boss 机制与掉落、局内买价/升星定价、经验→基础数值成长曲线、地图主题与具体布局、难度层级是否首发。

## 14. 界面规格（8 屏）

单路由 `/nebula-survivor` 内用 **phase 状态机**驱动，**不新增路由**（守 §0 边界）。

```
briefing(进场简报) → hangar(船坞·局外) → run(局内) ⇄ shop(商店) / pause(暂停)
                                            ↓
                                         result(结算) → hangar
```

| # | 屏 | 组件 | 进入 / 退出 | 关键约束 |
|---|---|---|---|---|
| 1 | 大厅卡片 | `lobby`（既有） | 大厅 → 本路由 | tagline 必须改（§0.1）；key art 去紫（§10.3） |
| 2 | 进场简报 | `ArcadeEntry` | 首次进入 | **不传 `onRequestClose`**（必须显式点「开始任务」）；BGM 就绪前按钮压住 |
| 3 | 船坞（局外） | 新建 `ui/Hangar.tsx` | 简报后 / 结算后 | 职业选择 + 武器库 + E 技升级；读写 `asternova.nebula.v1` |
| 4 | 局内 HUD | 新建 `ui/Hud.tsx`（拆自旧 God Component） | 开局 | 分区布局见 §14.4；**不可放进缩放容器** |
| 5 | 局内商店 | 新建 `ui/ShopPanel.tsx` | 波次节点 | 免费刷新 1 次后花金币 |
| 6 | 合成 / 背包 | 新建 `ui/LoadoutPanel.tsx` | 随时 | 3 槽 + 三合一刻痕 + 品级工艺 |
| 7 | 暂停 | `ArcadeEntry`（pause 变体） | P / Esc | 可 Esc 关闭（传 `onRequestClose`） |
| 8 | 结算 | `ArcadeResult` | 死亡 / 撤离 | 分数走 `records.ts`；元进度走 `save.ts` |

```

│ 左上 生存数据           中上 品牌       右上 系统键    │
```

## 15. 局外养成与存档

- **归属**：§14 的 **hangar**（局内 phase，不是新路由）。
- **命名空间**：`asternova.nebula.v1`（**与 `asternova.arcade.v1` 正交**）。
  - `arcade.v1` 被 `ArcadeRecord` 强类型锁死（best/plays/lastRoundId），塞元进度会污染其它四个游戏。
- **字段**：`{ version, coins, xp, classLevels, weaponStars, eskills, unlockFlags }`，逐字段净化 + 未知字段丢弃 + 坏数据不整体作废。
- **健壮性**：照抄 `records.ts` 的写法 —— 隐私模式/配额满退化为内存态，跨标签页订阅。

## 16. 共享层契约（重构必须遵守）

1. **弹层**：统一走 `ArcadeEntry`，不手写规则/简报弹层。Esc 语义由「是否传 `onRequestClose`」决定；**briefing 不传**（必须显式点击）。
2. **结算**：统一走 `ArcadeResult`（内部调 `submitRecord`，带 `roundId` 幂等）；**不要各游戏自己写 localStorage**。巨型标题按最长单词反推字号。
3. **portal 陷阱**：`--arcade-accent` 不跨 portal。必须**两者并存** —— 根节点 `arcadeAccentStyle(slug)` 负责首帧，`useArcadeAccent(slug)` 负责 portal 子树（挂 `<html>`、卸载还原）。
4. **缩放容器禁令**：**交互控件绝不放进 `transform: scale()` 容器**。旧版踩坑：真机移动 UA 下 `MobileLandscapeGameShell` 把整棵游戏子树按 0.2855 缩放，游戏被压成 **390×210 条带、HUD 折合 4.6px**。本作改为全屏自适应壳（§12.3）。
5. **副色消费**：用作用域 CSS 变量 `var(--arcade-accent)`，不用运行时拼接的动态类名。
6. **可访问性**：视觉盒 ≥24px、关键路径命中盒 ≥44px、文字透明度地板 `text-white/50`、全站琥珀焦点环。
