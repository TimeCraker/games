## 跨维度冲突裁决摘要

7 份设计稿在多处存在分歧（各维度独立产出所致）。下表列出关键冲突与裁决，后续章节按裁决后的统一数值展开。

| # | 冲突点 | 分歧 | 裁决 | 理由 |
|---|---|---|---|---|
| A | 画布朝向 | core=纵向720×1280 / tech=横向1280×720 / 其他=1180×700 | **纵向 720×1280** | 顶射角度发射（已锁定）需纵向；移动端竖屏单手是休闲主战场；ScaleFitGameStage 支持自定义 designW/H |
| B | 球 restitution | core=0.55（修复病根）/ rogue=0.92 / 旧版=0.98 | **0.55 基线**（core 方案） | 旧版 0.98 球无尽乱飞是用户抱怨的病根；0.55 让连击靠多星连锁而非单球永动 |
| C | 数值量级 | core/enemies=小数值（球伤1, 敌人HP3-8）/ rogue=大数值（球伤10, 敌人HP80-120, Boss HP800） | **小数值体系** | combo 倍率 1.0-5.0× 是核心设计，大数值稀释倍率意义；enemies 维度从"单回合期望输出反推 HP"逻辑严密 |
| D | 钉子分类 | core=8类 / rogue=4类(RPG化) / audio=4色 | **统一 7 类钉子 + 5 种敌人**（见 §③§⑤） | core 的 8 类最完整；融合 enemies 的 5 种敌人机制；audio 4 色映射为音色分组 |
| E | 敌人回合 | core/enemies=有回合制 / tech=砍掉回合制 | **保留轻回合制** | 砍掉回合 = 退回纯 Peggle 消除 = 零威胁（旧版病根）；enemies 的 telegraph 是"弹射×策略"耦合点；Boss 三阶段依赖回合推进 |
| F | 节点数 | core=8-10 / rogue=11 / enemies=10 / daily=8 | **普通Run 10节点(含Boss) / Daily 8节点** | 落在范围约束"8-10+Boss"；enemies 的 10 节点表最详 |
| G | 球种命名 | core=陨星 / rogue=星核 / meta=散射重锤 | **统一 3 球种：标准/重击/裂解陨星** | core 物理基线 + 统一天文命名；meta 的散射/重锤映射为同 3 球种的涂装别名 |
| H | 敌人命名 | core=飘游孢/裂壳者/脉冲兽/编织者 / enemies=Shardling/Sentinel/Swarm/Vortex | **5 种统一：飘游孢/裂壳者/裂解虫群/吞噬涡流/超新星核心** | 取 enemies 的机制（更深）+ core 的天文命名（身份） |
| I | 磁星引力模型 | core=k/r²(发散风险) / enemies=线性衰减(稳定) | **线性衰减 falloff=1-dist/r** | enemies 模型无奇点发散，已验证稳定；core 自标注了 r² 发散风险 |
| J | Boss | enemies=星渊吞噬者HP60三阶段 / rogue=HP800 / art=Eclipse星蚀者 | **星渊吞噬者 HP 60 三阶段 20/20/20** | enemies 设计最完整；HP800 是大数值产物弃用；Eclipse 作为外观别名 |
| K | 玩家生命 | core=HP20 / enemies=Shield20 / meta=HP100 | **HP 20（上限 30）** | 小数值体系；meta 的大数值 HP 统一缩放 |

## ① 总览与设计目标

### 1.1 一句话定位

**物理弹射 × 肉鸽构筑（Physics-Bounce Roguelite）**：顶射角度发射陨星穿越密集星阵，谐振连击逐级攀升，击碎星体/击杀熵兽，节点间选遗物构筑强化，终幕对决星渊吞噬者。对标 Peglin/Roundguard 公式，做 AsterNova 星海身份的原创设计。

### 1.2 要解决的核心问题（旧版病根诊断）

| 旧版问题 | 根因 | 本作解法 |
|---|---|---|
| 出手后零操控 | 弹弓抛物线一发不可控 | 顶射角度 + 预测线到首碰 + 引力舱回球 |
| 零威胁 | 纯消除无敌人 | 5 种熵兽 + telegraph 回合制 + 玩家 HP |
| 零变化 | 单一钉子类型 | 7 类钉子 + 5 种敌人 + 3 球种 |
| 零成长 | 无 meta 进度 | 星轨树 24 节点 + Daily 挑战 + 图鉴 |
| 零手感 | restitution 0.98 球乱飞 + 无 Juice | restitution 0.55 系统衰减 + 分级屏震/hitstop/拖尾/音阶 |
| 瞄准难用 | 弹弓 pullX 抛物线反人类 | Peggle 式顶射角度 + 鼠标指向/触屏拖动 |

### 1.3 范围约束（独立开发现实主义）

- **1 幕完整闭环**：10 节点（含 Boss），8-12 分钟单局
- **~20 遗物**：6C / 6U / 5R / 3L
- **3 球种**：标准 / 重击 / 裂解陨星
- **5 种敌人 + 1 Boss**：飘游孢 / 裂壳者 / 裂解虫群 / 吞噬涡流 / 超新星核心 / 星渊吞噬者
- **7 类钉子**：普通晶体 / 共鸣核心 / 生命星云 / 脉冲星 / 磁星 / 超新星残骸 / 引力舱
- **元解锁**：星轨树 24 节点 + Daily 挑战 + 图鉴
- **不做**：5 幕 / 100 遗物 / 多 Boss / 后端排行榜

## ② 核心玩法循环

### 2.1 情绪弧线（一次出手 = 一次完整情绪弧）

```
蓄力(瞄准) -> 释放(发射) -> 攀升(连击音阶) -> 结算(击碎/击杀/回球)
```

这是旧版"出手后零操控"的直接解药：预测线给控制感，连击音阶给攀升感，引力舱回球给奖励感。

### 2.2 单节点循环

```
AIMING -> LAUNCHING -> BALL_IN_PLAY -> SETTLING -> ENEMY_TURN -> CLEANUP_CHECK
  ↑                                                        ↓
  └────────────────── (未清空, 球数>0) ──────────────────────┘
                              ↓ (清空)
                        NODE_CLEAR -> RELIC_PICK -> AIMING (下一节点)
                              ↓ (Boss 死亡)
                           VICTORY
```

| 阶段 | 持续 | 玩家可操作 | 核心逻辑 |
|---|---|---|---|
| AIMING | 无限时 | 是 | 星象仪跟随指针，预测线实时刷新到首碰 |
| LAUNCHING | 1 帧 | 否 | setVelocity 注入初速度，combo 归零 |
| BALL_IN_PLAY | 球飞行 | 否 | 碰撞->击碎/伤害->combo++->音阶->HUD |
| SETTLING | 300ms | 否 | 球落定结算（入舱回球/出底失球/卡滞超时） |
| ENEMY_TURN | 1.5-2.5s | 否 | 存活熵兽按 telegraph 行动，扣 HP |
| CLEANUP_CHECK | 即时 | 否 | 检查节点清空条件 |
| NODE_CLEAR | 遗物选择 | 是 | 三选一遗物 |
| GAME_OVER | 结算 | 否 | HP 归零 / 球尽未清空 |

### 2.3 单局循环（10 节点）

节点 1-2 教学 -> 节点 3 晶体矿脉喘息 -> 节点 4-5 升温引入装甲 -> 节点 6 商店/事件补给 -> 节点 7-8 引入引力+计时器 -> 节点 9 精英检验 -> 节点 10 Boss。

### 2.4 元循环（跨局）

通关/失败 -> 星核结算 -> 星轨树点亮 -> 解锁球种/遗物/涂装 -> 下一局构筑池更深 -> Daily 挑战同种子比拼。

## ③ 机制与物理

### 3.1 画布与坐标系

- **逻辑画布**：纵向 720×1280（`ScaleFitGameStage defaultWidth={720} defaultHeight={1280}`）
- 原点左上，y 向下。物理坐标即像素坐标。
- 桌面两侧留黑填充星云背景 + 侧栏 HUD。

### 3.2 物理引擎配置（matter-js 0.20）

```ts
const engine = Engine.create({
  gravity: { x: 0, y: 1.15, scale: 0.001 },
  positionIterations: 8,
  velocityIterations: 8,
  constraintIterations: 4,
})

// 固定步长 + 子步防穿透
const FIXED_DELTA = 1000 / 60       // 16.667ms
const SUBSTEPS = 2                   // 等效 120Hz
// 每帧跑 2 次: Engine.update(engine, FIXED_DELTA / SUBSTEPS)
```

**防穿透验证**：vMax=16 px/step，子步位移 ≈ 6.7px < 球半径 9 + 钉半径 10 = 19px，安全裕度充足。

**移动端降级**（v0.2）：低端机回退 60Hz 单步 + 球半径 +1px（10px）。**自适应触发**：连续 N 帧帧时间 >33ms 切 30fps 单步 + vMax 降为 12，M4 真机验证降级后可玩性。

### 3.3 发射器（星象仪 / Astromancer）

| 参数 | 值 | 说明 |
|---|---|---|
| 锚点 | (360, 70) | 顶部中央 |
| 角度域 | -78° ~ +78° | 0°=正下方，左负右正；±90°水平禁用 |
| 初速度 v0 | 14 px/step | 60Hz 标定 |
| 速度钳制 vMax | 16 px/step | 防穿透 |

**输入适配**：
- 鼠标（桌面）：实时指向 + 单击发射
- 触屏（移动）：按下拖动预览 + 松开发射（防误触）

### 3.4 轨迹预测线（星轨预测）

**设计哲学：精确到首碰 + 首碰后 1 次弹射，其后模糊（保留长程混沌的惊喜）。**
> v0.2 修订：原"仅首碰"与本作"策略性敌人定位"（裂壳者穿缺口/涡流绕引力/超新星优先击破）冲突--核心决策常发生在首碰之后。延伸 1 次弹射给玩家"第二下会打到谁"的判断空间，仍非全程透视。

- 算法：与真实物理同源的数值积分，逐 step 推进幽灵球（**复用 PhysicsWorld.step() 同一段积分代码，含磁星/涡流引力，保证误差 <2px**）
- MAX_STEPS = 48（约 0.8s 飞行，~600px），超长渐隐；首碰后继续积分 ~12-16 步画第二段（更淡）
- 首碰标记：命中星体画脉冲光环 + 高亮
- 遗物增强钩子：`星图仪 Astrolabe` 延伸到第 3 碰；`先知视界 Foresight` 延伸到落点含 1 次墙反弹

### 3.5 球物理参数（陨星 / Meteor）

| 参数 | 值 | vs 旧版 | 说明 |
|---|---|---|---|
| restitution | **0.55** | 0.98->0.55 | 核心修复：每次碰撞显著衰减 |
| friction | 0.001 | 0->0.001 | 极低切向摩擦 |
| frictionStatic | 0 | 0 | 杜绝粘连 |
| frictionAir | 0.006 | 0.001->0.006 | 长程飞行收敛更快 |
| density | 0.005 | 0.0032->0.005 | 分量感 |
| slop | 0.02 | 0.05->0.02 | 密集钉阵碰撞更精确 |
| 半径 | 9px | - | 配合 vMax 防穿透 |
| label | "meteor" | - | 碰撞分类 |

### 3.6 连击系统（Nova 谐振 / Resonance）

**combo 累计**：单次出手内每碰一个星体 combo+1。永久钉（脉冲星/磁星）单次出手同一星体只计 1 次（Set<pegId> 去重）。

**中断条件**：陨星落定（入舱/出底/卡滞）| 陨星 |v|<1.5 持续 400ms。

**倍率曲线**：

| combo | 倍率 | 命名 | 屏幕反馈 |
|---|---|---|---|
| 1-2 | 1.0× | 谐振 | 无 |
| 3-5 | 1.5× | 共鸣 | 字号+10% |
| 6-9 | 2.0× | 协奏 | 轻微屏震 |
| 10-14 | 3.0× | 激荡 | 屏震+边缘辉光 |
| 15-19 | 4.0× | 超新星预热 | 屏震+色温升 |
| 20+ | 5.0× | Nova | 全屏闪白+BGM层叠加 |

**链爆防护**：超新星链爆单链最多计 8 combo；单次出手 combo 上限 30。

**伤害公式**：`hitDamage = ballBaseDamage × comboMultiplier`
**得分公式**：`score = pegScore × comboMultiplier`

**磁星引力实现**（统一线性衰减模型，解决 core 的 r² 发散问题）：

```ts
// beforeUpdate 每子步
for (const m of magnetars) {
  const dx = m.x - ball.x, dy = m.y - ball.y
  const dist2 = dx*dx + dy*dy
  const r = 80
  if (dist2 < r*r && dist2 > 100) {  // 防奇点
    const dist = Math.sqrt(dist2)
    const falloff = 1 - dist / r
    const fx = (dx/dist) * 0.08 * falloff * ball.mass
    const fy = (dy/dist) * 0.08 * falloff * ball.mass
    Body.applyForce(ball, ball.position, { x: fx, y: fy })
  }
}
```

**重要**：预测轨迹渲染必须同步磁星/涡流引力，否则瞄准线与实际弹道不符。

### 5.3 敌人回合 AI 调度

```
玩家回合: aiming -> flying -> resolve
        ↓ (球停止)
敌人回合: act(按优先级) -> resolve(结算telegraph) -> 清理死亡 -> telegraph(刷新下回合意图)
        ↓
玩家回合 (循环)
```

**优先级**：①超新星充能/爆发 -> ②裂壳者旋转+蓄能 -> ③吞噬涡流漂移 -> ④裂解虫群漂移 -> ⑤飘游孢(无行为) -> ⑥Boss(单独tick)

**残局模式**（v0.2，替代原全局保底）：池内球耗尽后不锁死，每回合仍可发 1 球，但敌人该回合行动 +1 次（透支惩罚）。既防"球尽未清"死锁，又保留"还剩 N 球必须清场"的生存张力。HP 归零是唯一硬败北（见 §3.9）。

## ⑧ 技术架构要点

### 8.1 一句话架构

常驻 `PixiApp`（全生命周期不销毁）承载渲染；纯 TS `GameEngine` 类持有 matter `Engine`/`Runner` 与全部逻辑；React 只做 UI overlay，通过 Zustand store 低频快照（~10Hz）与引擎单向通信。

**铁律：matter 只算物理 tick，Pixi 只渲染；高频游戏状态不进 React。**

### 8.2 数据流（单向）

```
输入: pointer -> engine.input.aim() -> PhysicsWorld (不经过React)
物理: Runner(60Hz) -> matter Engine.step -> Body.position更新
渲染: app.ticker(RAF) -> registry.syncAll() -> sprite.position=body.position
UI同步: RAF每~100ms -> engine.snapshot() -> useStaStore.setState (节流)
命令: React按钮 -> store.dispatch() -> engine.dispatch()
```

### 8.3 状态三层分层（避免 60fps 卡顿）

| 层 | 数据 | 存储 | 频率 | 谁读 |
|---|---|---|---|---|
| 高频 | 球位置、敌人坐标、粒子、peg命中态 | GameEngine 实例字段 | 60Hz | Pixi 渲染（不进React） |
| 中频 | HP、弹药、分数、combo、节点、phase | useStaStore（非persist） | ≤10Hz | React HUD/overlay |
| 低频 | 元进度、最高分、设置、Daily种子 | useStaMetaStore（persist） | 事件驱动 | React 设置/解锁弹窗 |

### 8.4 Body ↔ Sprite 映射（EntityRegistry）

- body 不持 sprite，sprite 反向持 body 引用只读位置
- `Map<bodyId, Entity>` 双向查表 + 对象池复用
- 避免 nova-ball 每帧 `Composite.allBodies().filter()` 全表扫的性能隐患，改用 `Set<activeBallBody>` O(1) 查询

### 8.5 固定步长

- matter Runner 默认固定步长 `delta=1000/60`，最多补 5 步防 spiral
- **保留 matter Runner 做物理，不让 Pixi ticker 驱动物理**
- 渲染侧 RAF 自适应，可选 Lerp 抹抖动（保留 alpha 参数位）

### 8.6 Phase 状态机（裁决后保留敌人回合）

```
menu -> aiming -> flying -> resolving -> enemy_turn -> cleanup_check
                                    ↓ node end
                          relic_pick -> briefing(下节点敌人+球种选择) -> aiming
                                    ↓ (Boss 死亡/HP≤0)
                                 result
```

| 转场 | 触发 | 引擎动作 |
|---|---|---|
| aiming->flying | dispatch("release")/松手 | 解除constraint, setVelocity, ammo-1 |
| flying->resolving | 球速<0.3持续0.6s/出界/5s无命中 | 停球,结算伤害与掉落 |
| resolving->enemy_turn | 非商店节点,有存活敌人 | 敌人按优先级act+resolve+telegraph |
| node_clear->relic_pick | 节点清空 | 弹三选一遗物 |
| relic_pick->briefing | 选完遗物 | 展示下节点敌人构成+球种选择UI |
| briefing->aiming | 球种选定(晶体矿脉跳过球种选择) | 生成新球,进入下节点 |
| resolving->shop | 每2节点 | 弹三选一 |
| resolving->boss | 第10节点 | 切Boss布局 |
| resolving->result | Boss死亡/HP≤0 | 写元进度,弹结算 |
| *->paused | dispatch("pause") | Runner.enabled=false |

### 9.3 每日挑战（Daily Constellation）

**种子**：`seed = 数值(YYYYMMDD)`，UTC 滚动。mulberry32 确定性 PRNG 驱动节点布局/敌人位置/遗物商店/Boss技能序列/掉落。**不驱动玩家决策**（构筑选择产生差异）。

**模式差异**：

| 维度 | 普通 Run | Daily |
|---|---|---|
| 种子 | 随机 | 固定(UTC日期) |
| 开局球种 | 自选(受解锁限制) | **固定3球种全给** |
| 起始加成 | 元进度解锁生效 | **禁用**（纯构筑比拼） |
| 遗物池 | 按星轨树阶梯开放 | **全员全池20件** |
| 长度 | 10节点 | 固定8节点+Boss |
| 重开 | 任意 | **每日3次有效提交，取最高分**（v0.2：原1次对休闲过苛） |
| 计分 | 局内分数 | 专用Daily公式 |

**Daily 分数公式**：
```
dailyScore = 1000 × nodesCleared
           + 250  × uniqueRelicsCount
           + 300  × remainingBalls + 5 × remainingHpPct
           - 50   × hpLost
           + 500  × noDeathFlag
           + 800  × bossKilledFlag
```
梯度约 8000-22000。

**排行榜（无后端三层）**：
1. 本地榜：自己历史所有 daily 成绩
2. 好友榜（分享码）：导出成绩为分享码，朋友粘贴归入好友榜按种子分组
3. 个人最佳榜：跨日 Daily Top 5

**分享码**：紧凑二进制 + HMAC-SHA256 签名(前8字节) + Crockford Base32，约32-40字符。防君子不防黑客（前端硬编码密钥可被提取），UI 须标注"本地成绩，自助校验"。
